# Enhanced CFDI Automation API - Ticket Upload & Processing

## New Endpoints for Ticket Upload System

### 1. Upload and Process Ticket
- **Endpoint:** `POST /api/v1/tickets/upload`
- **Purpose:** Upload ticket file (image/PDF) and optionally provide vendor URL for processing
- **Access:** Private (requires JWT token)
- **Content-Type:** `multipart/form-data`

**Input:**
```javascript
// FormData fields:
{
  "file": File, // Image or PDF file (any format accepted)
  "vendor_url": "https://facturacion.walmartmexico.com.mx/", // Optional
  "vendor_name": "Walmart Mexico", // Optional - for vendor detection
  "priority": "normal" // Optional: "low", "normal", "high"
}
```

**Response (Success - 201):**
```json
{
  "success": true,
  "data": {
    "ticket_id": "ticket_67890abcdef",
    "status": "PROCESSING",
    "file_info": {
      "filename": "walmart_receipt_001.jpg",
      "size": 2048576,
      "type": "image/jpeg"
    },
    "vendor_url": "https://facturacion.walmartmexico.com.mx/",
    "vendor_detected": "Walmart Mexico",
    "estimated_processing_time": "30-45 seconds",
    "created_at": "2024-01-01T00:00:00.000Z"
  }
}
```

### 3. Create Agent Task from Extracted Data
- **Endpoint:** `POST /api/v1/tickets/:ticketId/create-agent-task`
- **Purpose:** Create browser automation task using extracted ticket data + user profile
- **Access:** Private (requires JWT token)

**Input:**
```json
{
  "vendor_url_override": "https://custom-vendor-url.com", // Optional override
  "task_priority": "high", // Optional: low, normal, high
  "auto_start": true, // Start agent immediately
  "manual_review_required": false // Force manual review before agent starts
}
```

### 4. Agent Task Control
- **Endpoint:** `POST /api/v1/agent-tasks/:taskId/control`
- **Purpose:** Control browser agent (pause, resume, take control)
- **Access:** Private (requires JWT token)

**Input:**
```json
{
  "action": "pause", // "pause", "resume", "take_control", "stop"
  "reason": "User intervention required" // Optional
}
```

**Response:**
```json
{
  "success": true,
  "data": {
    "task_id": "agent_task_12345",
    "action": "pause",
    "status": "PAUSED",
    "browserbase_session": {
      "session_id": "browserbase_session_789",
      "live_view_url": "https://www.browserbase.com/sessions/browserbase_session_789",
      "user_control_enabled": true,

    },

    "timestamp": "2024-01-01T00:01:15.000Z"
  }
}
```

### 7. Delete Ticket
- **Endpoint:** `DELETE /api/v1/tickets/:ticketId`
- **Purpose:** Delete ticket and associated data
- **Access:** Private (requires JWT token)

**Response:**
```json
{
  "success": true,
  "data": {
    "ticket_id": "ticket_67890abcdef",
    "message": "Ticket and associated data deleted successfully",
    "deleted_items": {
      "ticket_file": true,
      "extracted_data": true,
      "agent_task": true,
      "browserbase_session": "terminated"
    }
  }
}
```

## Database Schema Updates

### New Tables Required:
```sql
-- Ticket uploads table
CREATE TABLE ticket_uploads (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES auth.users(id),
    filename VARCHAR(255) NOT NULL,
    file_size BIGINT NOT NULL,
    file_type VARCHAR(50) NOT NULL,
    file_url TEXT NOT NULL, -- Supabase storage URL
    vendor_url TEXT,
    vendor_name VARCHAR(255),
    vendor_detected VARCHAR(255),
    vendor_confidence DECIMAL(3,2),
    status VARCHAR(20) DEFAULT 'PROCESSING',
    processing_stage VARCHAR(50),
    progress_percentage INTEGER DEFAULT 0,
    extracted_data JSONB,
    ocr_metadata JSONB,
    agent_task_id UUID,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    completed_at TIMESTAMPTZ
);

-- Indexes for performance
CREATE INDEX idx_ticket_uploads_user_id ON ticket_uploads(user_id);
CREATE INDEX idx_ticket_uploads_status ON ticket_uploads(status);
CREATE INDEX idx_ticket_uploads_created_at ON ticket_uploads(created_at DESC);
```

This implementation provides:

1. **Complete separation of concerns** - each team can work independently
2. **Comprehensive mock data** for development and testing
3. **Real-time updates** via WebSocket for live progress tracking
4. **Flexible agent control** with pause/resume/takeover capabilities
5. **Rich data extraction** beyond the 4 core fields as requested
6. **Vendor URL handling** with optional override functionality
7. **Dashboard integration** without page redirects

The mock data provided allows each team member to develop their components independently while maintaining consistency across the entire system.
